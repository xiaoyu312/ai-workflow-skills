# 口径与对账

生成或更新 `evidence/source_snapshot.json` 时用这些字段。缺字段就停，不要补 0。

## 快照字段

- `source`：工作簿名、revision、本周期间、对照期间、正常基线期间、读取 range、抽取时间
- `quality_findings`：标签错误、#REF!、空导出、源表备注口误、覆盖范围缺口
- `weekly`：至少三周。每行含 spend, gmv, roi, aov, cpc, cvr, impressions, clicks, ctr, cart_cost, fee_rate, baseline_type
- `scenes`：本周 + 对照周，五条通道都要有
- `scenes_baseline`：正常周分场景；没有就写进质量问题，不能用对照周顶替
- `keyword_categories`：本周 + 对照周
- `audiences`：智能 / 类目 / 品牌 / 竞品，含 spend, share, gmv, roi
- `high_spend_keywords`：消耗阈值由用户或当前任务明确；条数以源表为准
- `named_audiences`：本周命名人群包
- `product_lines`：写清覆盖哪些场景
- `monthly_progress`：消耗、推广GMV、店铺GMV、费比、ROI、推广占比
- `monthly_scenes`：月度分场景，消耗合计对账月消耗
- `operator_notes`：每条带 period 和 layer

百分比、费率、完成率存小数。金额存元。`aov` 在零成交时为 `null`，不是 0。

## 公式

- 环比 / 较正常周：`current / prior - 1`；`prior == 0` → 不适用
- ROI：`gmv / spend`，允许源表四舍五入误差约 0.005
- 漏斗验算：`cvr * aov / cpc` 应接近 ROI
- 客单结构：`sum(本周场景订单数 × 对照周该场景客单) / 本周总订单`；订单数 = `gmv / aov`
- 店铺直达抵消率：`店铺直达GMV增量 / 其它场景GMV净降幅`；其它场景含短视频正负向
- 关键词浪费：零成交消耗、低于用户确认 ROI 阈值的消耗，各自除以本周关键词消耗
- 月完成率：`actual / plan`；源表整数百分比允许 1.5 个百分点误差
- 剩余消耗：`(月计划消耗 - 已耗) / 剩余天数`，再和本周日均比

## 对账，失败即停

1. 三周都在，且本周 / 对照 / 正常周标记清楚
2. 分场景消耗合计 = 该周总消耗（容差 1 元）
3. 分场景 GMV 与周总 GMV 残差 ≤ 2 元
4. 关键词分类消耗合计 = 关键词推广消耗
5. 人群分类消耗合计 = 人群推广消耗
6. 命名人群消耗与人群推广残差记下来，不补 0
7. 货品线消耗 = 其所称覆盖场景之和
8. 月度分场景消耗 = 月进度消耗

## 质量问题怎么记

- 子表标签期间 ≠ 单元格期间：用单元格，记一条
- 本地 XLSX 无网格：不提升为控制源
- 透视表 `#REF!` 或明细为空：分类占比不从明细“还原”
- by day 不覆盖本周：不做逐日曲线，不编日点
- 源表环比行抄了总计行：按单元格重算，弃源表该行
- 备注把占比变化写成消耗变化：单元格优先

## 拒绝清单

- 对照周有异常展现时，把 CPC / CVR / 点击环比写成策略一夜变好
- 只报环比 ROI 上涨，不报对照正常周
- 把智能人群占比提升写成消耗上涨
- 把内容场 / 小红书 / 发券写成已证实原因
- 把消耗几十元、ROI 很高的词当成扩量样本
- 货品线没覆盖的场景，拿货品线 ROI 解释全店
