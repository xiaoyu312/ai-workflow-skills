# 镜头规划与回片检查

把用户的镜头要求交付为可执行的文字方案。该版本保留通用镜头策划用途，不提供特定作者的方法库，也不预设某个视频平台的当前能力。用户只要提示词时，交付文字即可；已有生成授权时沿其范围工作。

## 从现有状态选择任务

先判断用户提供的是需求、参考资产、已生成片段还是局部问题。只询问会改变方案的缺项；其他缺项写为假设或待核对。

| 当前材料与目标 | 处理方式 | 要补充的最少信息 |
|---|---|---|
| 只有想法或静态参考 | 新镜头方案 | 可见动作、结束画面、片长目标 |
| 已有片段主体合格，只缺结尾 | 后续段或延长方案 | 原结尾状态、要新增的事件 |
| 某处内容不合格，其余希望保留 | 局部修改方案 | 问题区间、修改对象、须保留的部分 |
| 两段均可用但衔接不顺 | 过渡或剪辑建议 | 前段末态、后段初态、允许新增的动作 |
| 主体动作与机位难以表达 | 先做简单空间预演 | 物体位置、相机路径、必须看到的关系 |

这些是任务选择，不是平台功能声明。实际生成前核对当前入口是否支持所选操作、素材类型和时长；未核对时不要给出硬上限或承诺。已有素材合格的部分优先复用，局部修改不自动扩大为全片重做。

## 整理参考与时间

用 [镜头卡](assets/shot-card.md) 记录本镜，按任务删减无用字段。

- 为每份实际提供的资产分配一个引用 ID，说明它只约束外观、构图、场景、动作还是声音。未提供或未查看的资产标明状态，不声称已锁定外观。
- 参考画板上的多张图可能代表多个镜头，也可能是同一动作的不同时刻；先解释它们的用途，再确定生成镜头数。画板边框和注释通常不属于成片。
- 分开记录原素材时间、拟生成片段内时间和成片时间。没有真实帧率时使用秒和近似切点；不要承诺帧级卡点已经实现。
- 修改现有分镜时至少核对相邻镜头的结束与开始状态；保留用户已批准的镜头顺序和素材选择。

## 写成可见的动作方案

确定本镜需要传达的信息，再填写以下内容：

1. **开始与结束**：分别描述能看到的画面，不只写情绪或风格词。标明哪些是用户事实、哪些是本轮建议。
2. **动作顺序**：用简单、可连贯完成的动作连接两端。短镜中如果多个事件无法看清，删减次要事件或建议拆镜，而不是用“更快”掩盖矛盾。
3. **相机与空间**：分开描述主体运动和相机运动，给方向一个明确参照，例如物体自身方向或画面方向。环绕时画面左右可能变化；不能同时要求冲突的空间约束。
4. **变化边界**：区分全程应稳定的身份、外形等信息与需要发生变化的姿态、接触或光影。需要精确保真的对象，只使用已有证据支持的角度与结构。
5. **接入与接出**：说明与前后镜衔接的动作、视线或构图。没有相邻镜头资料时列出接口假设，不能替用户改写整段叙事。

只有相机相对主体的距离或取景范围发生变化时，景别才会相应改变。不要把整体画面放大、背景漂移或装饰性形容词当作已实现的运镜证据。多物体接触或复杂动作已经足够困难时，可先固定机位。

## 交付提示词与制作备注

先给简短任务选择及理由，再给镜头卡、可复制提示词和待核对事项。用户只改一处时，只交变化及保留项，不重复整份项目文档。

提示词写实际画面与动作；上传顺序、界面参数、素材使用范围、后期剪辑和未确认事实另列。已合格参考中明确提供的信息可简写；有空间冲突、接触或阶段变化时再增加解释。没有依据时不写当前平台支持某模式、时长或精度。

生成多个镜头时列清镜头数、每镜目标及拟定区间，并核对总时长。文字时间安排只是制作计划，实际返回后仍需读回核验。字幕、声音或包装信息缺少可靠输入时保持为空或列待补，不凭空创造品牌事实、功效或可见文字。

## 根据回片证据决定下一步

没有视频时，只做方案检查；有可查看视频时，观察开头、动作转换、遮挡或接触处、结尾以及镜间连接，报告实际看到的问题和时间位置。

| 观察到的问题 | 优先处理 |
|---|---|
| 起始状态与任务不符 | 修正输入或首段描述 |
| 动作拥挤、突然跳变、接触关系错误 | 减少事件或拆段，明确动作顺序 |
| 主体合格，局部出现瑕疵 | 给局部编辑范围及保留项 |
| 主体与背景相对运动不符合方案 | 明确相机相对路径，必要时做空间预演 |
| 结尾缺少衔接余量 | 设计后续段、延长或剪辑余量 |
| 形状、文字或身份失真 | 用已核验参考约束；必要时建议后期合成 |

一次优先修复最影响任务的一项，记录改动原因和实际结果。比较两版时同步记录提示词、参考、模型/模式和参数；多项同时变化，不能把效果差异归因给一个词。

交付状态使用“文字方案完成”“已提交生成”“已收到素材”“已查看并验收”等实际完成状态。没有观察到素材，不写“通过验收”或“已生成”。
